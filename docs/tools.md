## `unit`

Unit of work bookkeeping: start, status, list, brief, explain and advance through the core stages. Actions: start, status, list, brief, explain, advance.

- `start` — Create a unit from a source (ticket, pr, url, file, conversation, text) and pin its text.
- `status` — One-line status of a unit.
- `list` — List every unit in the current repo namespace.
- `brief` — Render the brief for a stage: header, seats, config problems, source, then stage material.
- `explain` — Describe the next stage, the gates guarding the move, the seats consulted and what it produces. Mutates nothing.
- `advance` — Move a unit to its next stage when the current stage gates allow it; otherwise list the remedies.

## `spec`

Requirement context for a unit: record the normalized requirement, pin the source, number acceptance criteria, link related items. Actions: record, pin, criteria, related, get.

- `record` — Write requirement.md (title, url, body) and set the unit kind, inferring bug from the wording when not given.
- `pin` — Pin the verbatim source text into source.md and mark the source pinned.
- `criteria` — Set (renumbering as AC-1…) or read the acceptance criteria in requirement.md.
- `related` — Record related items (parent, siblings, linked docs, prior PRs) in related.md.
- `get` — Return the requirement, criteria, pinned source and related items for a unit.

## `system`

Engine housekeeping: version, health, doctor, configuration, inference and sync. Actions: version, health.

- `version` — Report the engine version.
- `health` — Report whether the vault is initialized and which Node runs the server.
