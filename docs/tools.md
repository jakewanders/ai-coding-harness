## `unit`

Unit of work bookkeeping: start, status, list, brief, explain and advance through the core stages. Actions: start, status, list, brief, explain, advance, report, route, answer, reconcile.

- `start` — Create a unit from a source (ticket, pr, url, file, conversation, text) and pin its text.
- `status` — One-line status of a unit.
- `list` — List every unit in the current repo namespace.
- `brief` — Render the brief for a stage: header, seats, config problems, source, then stage material.
- `explain` — Describe the next stage, the gates guarding the move, the seats consulted and what it produces. Mutates nothing.
- `advance` — Move a unit to its next stage when the current stage gates allow it; otherwise list the remedies.
- `report` — Store a stage report (outcome, summary, questions, verdict, artifacts) for the current cycle; a ship verdict at challenge marks it passed.
- `route` — Decide the next stage from the reports (proceed, retry, blocked, done); applies the move when gates allow it.
- `answer` — Store the user's answers to blocked questions.
- `reconcile` — Compare stored state with live facts you gathered (branch, uncommitted work, PR state, tracker status); reports disagreements, mutates nothing.

## `spec`

Requirement context for a unit: record the normalized requirement, pin the source, number acceptance criteria, link related items. Actions: record, pin, criteria, related, get.

- `record` — Write requirement.md (title, url, body) and set the unit kind, inferring bug from the wording when not given.
- `pin` — Pin the verbatim source text into source.md and mark the source pinned.
- `criteria` — Set (renumbering as AC-1…) or read the acceptance criteria in requirement.md.
- `related` — Record related items (parent, siblings, linked docs, prior PRs) in related.md.
- `get` — Return the requirement, criteria, pinned source and related items for a unit.

## `analyze`

Deterministic analyses over the diff and PR prose; each one records its result as evidence of the matching kind. Actions: impact, pii, claims, reach, criteria_map.

- `impact` — Impact radius: changed exports and the files importing them; records impact evidence.
- `pii` — Personal-data audit over added lines; records pii evidence (empty findings means clean).
- `claims` — Extract assertive claims from PR prose (default: drafts/pr-body.md) and record them as unverified claims evidence.
- `reach` — Coverage-reach audit: new files, exports and routes and the e2e/mock/contract subject files that mention them; records reach_audit evidence.
- `criteria_map` — Map acceptance criteria to hunks by keyword overlap; records a provisional criteria_validation (matched criteria still need real proof).

## `evidence`

Record and inspect quality evidence for a unit and see which gates it satisfies. Actions: record, list, gates, check, synthesize.

- `record` — Validate a payload against its evidence kind and append it for the current cycle.
- `list` — List evidence records, optionally filtered by kind and cycle.
- `gates` — Resolve the gates for the unit's current stage (or a named stage) with live pass/fail status.
- `check` — Resolve one gate by id for the unit and report its status and remedy.
- `synthesize` — Merge this cycle's review columns into one verdict (ship, needs_attention, not_ready); writes reviews/cycle-<n>.json and state.reviews.

## `diffaudit`

Configured and kit diff-audit rules run over added lines; results are recorded as the diffaudit review column. Actions: run, rules.

- `run` — Run every rule over the diff (default: worktree vs remote base) and record the diffaudit review column.
- `rules` — List the diff-audit rules in effect for this repo (config plus kits).

## `exec`

Run profile or ad-hoc commands for a unit with full logs kept under runs/ and a summary in state. Actions: commands, run, logs.

- `commands` — List the repo profile commands for the unit's repo, inferred with evidence when nothing is configured.
- `run` — Run a named profile command or a raw command in the unit worktree; records exit, summary and log path.
- `logs` — Return the full log of a recorded run, or its last N lines.

## `vcs`

Git bookkeeping for a unit: fetch, diff against the remote base, branch, worktree, status, gated commit, cleanup. Actions: fetch, diff, branch, worktree, status, commit, cleanup.

- `fetch` — git fetch origin --prune; reports whether a remote exists.
- `diff` — Fetch, then diff the working tree against origin/<base_branch> (or HEAD); unified or --stat, capped at 200 KB.
- `branch` — Create or check out the unit branch (<id>-<slug>) from the base branch.
- `worktree` — Isolate the unit per repo capability isolation: a sibling worktree ../<repo>-<id>, or a branch in place.
- `status` — Porcelain status of the unit worktree with ahead/behind counts.
- `commit` — Commit everything in the worktree once the commit-stage gates pass; records the commit and moves the unit to review.
- `cleanup` — Remove the unit worktree, delete its branch if merged into the base, and clear state.worktree.

## `pullreq`

Pull request bookkeeping: ghostwritten body from the record, PR and thread records, worklog suggestion. Actions: body, record, threads, get, worklog.

- `body` — Render the PR body from the unit record and save it as drafts/pr-body.md.
- `record` — Record the opened pull request on the unit and stop the running stage timer.
- `threads` — Replace the recorded review threads on the PR.
- `get` — Return the recorded PR with its threads.
- `worklog` — Suggest a worklog from the stage timers: minutes per stage with idle gaps subtracted.

## `ledger`

Per-repo carry-forward ledger: standing asks and past landings that every later unit re-verifies. Actions: add, list, recheck, close.

- `add` — Add a carry-forward entry (ask = standing request, landing = past change to protect).
- `list` — List ledger entries for a repo, optionally filtered by status.
- `recheck` — Mark an entry rechecked against a unit, with an optional note.
- `close` — Close an entry with a reason; closed entries no longer need rechecking.

## `digest`

Story summaries for a unit: the digest and its keyword index, the running history, a handoff note, and the wrap-up. Actions: write, get, history, handoff, wrapup.

- `write` — Write digest.md (summary, decisions, tags) and update the cross-unit keyword index.
- `get` — Return the digest for a unit.
- `history` — Append a line to the unit history when `line` is given; otherwise return the history.
- `handoff` — Render a handoff note (where things stand, open questions, next action) and save it to drafts/handoff.md.
- `wrapup` — Render the wrap-up: PR link, stage table, scope ledger, not-built list, held drafts, and Not proven for reduced modes.

## `recall`

Cross-unit search over digests by keyword, and rebuilding of the digest index. Actions: search, reindex.

- `search` — Keyword search over all digests (term overlap, tags weigh double); returns the top hits.
- `reindex` — Rebuild index/digests.json from every digest.md in the vault.

## `system`

Engine housekeeping: version, health, doctor, configuration, inference and sync. Actions: version, health.

- `version` — Report the engine version.
- `health` — Report whether the vault is initialized and which Node runs the server.
